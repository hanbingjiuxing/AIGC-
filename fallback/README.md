# 离线应急页（fallback/）

这里放着一份**不需要启动系统就能看的**「关于这个系统」页面。

## 为什么要有这一页

系统里的 About 页（`frontend/src/pages/About.jsx`，路由 `/about`）末尾那一节
正是「遇到实在解决不了的 bug」—— 它告诉你在系统出问题时该找谁。可它本身是系统的
一部分：系统起不来，就看不到它。所以把这一页复制一份出来，做成：

- **单文件 HTML**：样式、社徽、脚本全部内嵌，没有 React / Vite，没有任何外部请求；
- **不依赖后端**：双击 `about.html` 就能看（`file://` 也可以），手机上打开也行；
- **跟随主题**：默认跟随系统深浅色，也可以点左上角按钮切换；
  想在命令行里指定，用 `about.html?theme=dark` 或 `?theme=light`。

## 什么时候会被打开

`run_system.bat`（以及 `backup\run_system_backup.bat`）启动时会等后端
（5000）和前端（5173）两个端口真正就绪：

| 情况 | 脚本行为 |
|------|----------|
| 两个端口都起来 | 打开 `http://localhost:5173`（正常启动） |
| 没找到 Python / 后端依赖缺失 | 打印原因，**自动打开本页**，退出码 1 |
| 找不到 npm，或 60 秒内端口没起来 | 打印哪个服务没起来，**自动打开本页**，退出码 1 |
| 端口早有别的程序在用 | 打印 `[WARN]`，正常继续（可能是上一次没关干净的实例） |

被自动打开时，浏览器地址栏就是本页文件路径，形如：

```
fallback\about.html
```

## 这一页和系统里那一页的差别

内容（来源 / 实现与协议 / 联系方式 / 协议表）与系统里完全一致，由脚本逐句核对。
只有三处是有意不同的：

1. 左上角的「返回」按钮换成了**浅色/深色切换** —— 离线时没有系统可返回；
2. 顶部多了一条说明、底部多了一行标注，点明这是离线副本；
3. **联系人头像退回社徽**。头像是加密存放在 `assets/encrypted/` 里的，只有后端
   解密才拿得到（密钥内置在程序里，所以系统正常运行时一定有头像）；离线页没有
   后端、也不把明文图片写进仓库，所以这里显示社徽。
   如果这一页恰好是**通过后端打开的**（例如将来把它挂到站点上），脚本会自动把
   头像换成 `/api/assets/avatar`。

## 怎么重新生成

本页由脚本生成，**不要手工编辑** `about.html`：

```bash
python scripts/build_about_fallback.py          # 重新生成 fallback/about.html
python scripts/build_about_fallback.py --check  # 只检查磁盘上那份是否最新（CI / 提交前用）
```

生成器会：

- 把 `frontend/src/index.css` 里的主题变量与「关于这个系统」整节样式原样摘出来；
- 从 `About.jsx` 直接解析 `CONTACTS`、`PROTOCOLS` 两处数据，并逐句核对页面文案；
- 把社徽 `frontend/public/logo.png`（与 favicon）以 base64 内嵌。

所以：**改完 `About.jsx` / `index.css` 之后重新跑一次**。忘了同步的话，
生成器会直接报错告诉你哪一句对不上，不会悄悄产出一份过期的离线页。
